# E2E architecture

Initial implementation lives in `tools/e2e` with its own package and lockfile. This avoids changing the user's root package/lockfile and keeps Playwright specs outside Vitest's webapp root and TypeScript application include. Cost: a second npm install/lockfile, explicitly documented; can later consolidate in a reviewed change.

Structure: package.json/package-lock.json; playwright.config.ts; global-setup.ts for real backend readiness; fixtures.ts for isolated contexts and sanitized diagnostics; tests/anonymous.spec.ts for login/deep-link gates; tests/security.spec.ts for unauthenticated API rejection. Reports live under `target/e2e`, already root-ignored. No new production code or test IDs needed for the initial accessible locators.

Use feature/test IDs in test names; roles and accessible text before CSS. Add page objects only after repeated workflows emerge. No automatic backend startup: existing containers are not known disposable and Liquibase can mutate their database. Explicit E2E_BASE_URL must be loopback; preflight reads /management/health and requires status UP. Browser page contexts are fresh; API requests use JSON Accept to avoid confusing an OIDC redirect with authentication rejection.

Initial run uses Chromium, one worker, zero retries, failure screenshots/traces, bounded timeouts and HTML/list/JUnit reports. Console/request failure attachments contain only category, host/path and status, not tokens/query values. Synthetic test environments are still required because traces/screenshots may capture response bodies and credentials; restrict artifact access and retention. Do not record real credentials or reuse production storageState. Authentication helper in the next vertical slice must log in through actual OIDC UI using environment credentials and verify /api/account + /api/rbac/me; keep auth state out of Git and isolate each write worker/identity.

Future fixtures provision UUID-prefixed users/zones/households via controlled API/admin setup against isolated PostgreSQL and Keycloak. Maintain a resource ledger and teardown in reverse relationship order even after failure. Keep setup errors as failures, not skips. Patrol append-only fixtures require disposal of the test database rather than bypassing production deletion restrictions. DOM tests with mocked routes are component/contract tests and must not be labeled real E2E.

CI: runner checks out root, installs locked root deps, executes fast checks, then installs `tools/e2e` deps with npm ci, installs Chromium OS dependencies, provisions disposable DB/IdP and starts backend. Run readiness then smoke/full suite. Upload restricted reports on failure; dispose only resources created by that job. No existing CI workflow was found; a deployment-specific runner configuration remains to be implemented after runtime provisioning is established. Browser and authentication capabilities referenced in the design follow [Playwright configuration](https://playwright.dev/docs/test-configuration) and [authentication documentation](https://playwright.dev/docs/auth).
