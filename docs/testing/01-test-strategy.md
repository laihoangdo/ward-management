# Test strategy

Retain JUnit/Mockito/ArchUnit, Spring MockMvc/Testcontainers and Vitest/Testing Library. Fix baseline test aliases/types as separate reviewable work; do not alter business rules or discard failing suites. Introduce Playwright only for real browser workflows: Vitest happy-dom cannot verify OIDC redirects, browser storage, downloads, canvas/WebGL or real persistence. Selenium is a viable alternative but adds driver/wait management; Cypress would be another new dependency without an existing investment here.

Playwright supports projects, startup readiness, configurable artifacts/reporters and authentication state reuse ([configuration](https://playwright.dev/docs/test-configuration), [authentication](https://playwright.dev/docs/auth)). Costs include browser downloads, CI OS dependencies, test-data provisioning and artifact protection. Start Chromium, expand Firefox/WebKit after actual feature compatibility is understood; use controlled provider doubles only in explicitly labeled component tests, retaining real contract tests separately.

Priorities: P0 session/locked user and territorial read/write/list/count/export/delegation isolation; household/resident persistence and partial failure; P1 document renewal/reminder semantics, append-only patrol, search/pagination, camera/OCR failure and correction; P2 maps, local preferences, responsive behavior and screenshot/download compatibility. No visual golden snapshots initially: live tiles/WebGL make them unstable without controlled data and renderer.

PR checks: Java unit/architecture, lint, tsc, Vitest, Vite build and read-only smoke. Changed records/security modules require scoped API integration and relevant authenticated E2E on disposable services. Nightly/full: all roles, DB migrations, cross-browser/mobile, offline failures, OCR known-image fixtures, provider contracts and complete write journeys. Do not run mutating scripts against existing local containers without establishing isolated ownership.

Use unique run/test IDs, example.invalid identities, synthetic personal data, per-test browser contexts, API setup and teardown in finally blocks. Verify UI and fresh server read after reload; reject forbidden operations and compare pre/post state. A green HTTP response alone is insufficient. No sleeps, no order dependencies, no blanket retries (initially zero). State flakiness separately after observed intermittent failure; no current tests are classified flaky without rerun evidence.

The initial foundation deliberately uses read-only smoke and real unauthenticated requests. Its readiness failure is a blocker, not a passing or skipped journey. Complete authenticated CRUD requires a disposable PostgreSQL/Keycloak environment, fixtures and requirements; no real credentials are in source. Feature matrix documents planned versus executed tests.
