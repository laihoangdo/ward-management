# DB-backed delegation road selection

Users and area assignments already use RBAC server APIs. Replaced fixed example/free-text road entry in SubAdminDelegationTab with multi-select options from a new /api/rbac/delegation-roads endpoint. The endpoint authenticates and uses HouseholdQueryService, preserving its existing RBAC record scope, rather than an unrestricted SQL query. Distinct nonblank street/alley values are associated with their area-zone IDs; households lacking an area ID are excluded. No road names or administrative units invented or seeded.

Frontend road options depend on selected area IDs. Existing road assignments are retained as options even when absent from current records, avoiding silent data loss. Fetch failure disables the road selector and preserves existing assignments. Repeated hamlet filter names are deduplicated and matching is exact instead of substring matching. Server delegation/version/permission rules remain unchanged; no live assignments or DB data were written.

Verification: root TypeScript passed; existing 28 Vitest suites / 205 tests passed, and the new component regression passed separately (DB area/road display, exclusion of another area's road, retention of legacy assignment). Targeted DelegationRoadTest passed after rebuilding missing local class output; verifies distinct road/alley extraction via the scoped query and exclusion of unassigned records. The first test attempt failed due to missing KeycloakAdminClient.class in local build output, not a road assertion; Maven recompilation repaired the test classpath without disabling IDE auto-build. git diff --check passed.

Limits: these are road names recorded on households, not an exhaustive official road network. The endpoint currently reads all scoped household DTOs to derive distinct values; a dedicated scoped projection/pagination is needed for very large datasets. The area assignment contract still uses area_zone IDs, not the independent hamlet administrative-unit catalog. No speculative mapping between the two was added. No authenticated browser or live database acceptance run executed.
